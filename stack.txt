EVALUATED AND DELIBERATELY NOT INCLUDED
==============================================================================

  PR #39721 / #39722 / #39723 / #39724  @Shunkangz
      [Qwen3.8 CP 1/4 .. 4/4] Collocated prefill context parallelism
      https://github.com/sgl-project/sglang/pull/39724  (4/4 contains 1..3)

      Reviewed 2026-09-16, not merged. Reasons:

      1. Wrong interconnect. These cards have no NVLink (`nvidia-smi nvlink -s`
         reports 'Device does not have or support Nvlink'; topology is NODE, i.e.
         PCIe via host bridges). CP adds per-layer all-gathers of K/V and index-K
         on top of TP traffic. #39722 was benchmarked on 4x B200 over NVLink.

      2. The required config removes most of the serving setup. The hook in
         #39723 refuses to start unless radix cache AND chunked prefill are
         disabled, plus no EP / PP / a2a backend / DP attention / spec decode /
         PD, and it force-disables prefill CUDA graphs. That also makes it
         mutually exclusive with HiCache (#39862).

      3. Conflicts with #38209 above. #39721 rewrites
         QSAMetadata.get_prefill_mqa_inputs against the pre-#38209 Python loop.
         One file, two hunks, but it is a semantic conflict: the resolution is to
         keep the fused packer and branch the row-range computation on whether
         query_sequence_ids is set. build_qsa_row_ranges still exists, so it is
         tractable -- it just is not a mechanical merge.

      4. All-or-nothing. _SUPPORTED_MODELS is empty until 4/4 registers
         Qwen4ExpForConditionalGeneration, so 1/4-3/4 alone are dead code.

      Local branches pr39721..pr39724 are kept for reference if long-context
      prefill is revisited.

==============================================================================
CAVEATS
==============================================================================

  * Do NOT enable --enable-hierarchical-cache on this model yet.
    #39862 fixes one real bug (PLE short-conv + N-gram state was lost through
    the host tier, so a restored slot inherited the previous occupant's token
    history) but the PR author's own measurement says host-tier hits still
    return wrong output: 0/10 usable answers vs 10/10 cold and 10/10 device-hit.
    Tracked upstream as issue #39830, still open.
    https://github.com/sgl-project/sglang/issues/39830

  * #39862 needed a follow-up fix (the last commit in the stack). Upstream unit
    tests build MambaPoolHost with __new__ and never run __init__, so the
    attributes #39862 adds there were missing and every reader raised
    AttributeError. It broke two tests that pass on upstream main; the second
    only appeared once the 2026-09-17 upstream merge brought in the NPU mamba
    test (#32500). Empty class-level defaults restore the intended no-op path.

  * sglang is installed EDITABLE against this checkout
    (/root/sglang/sglang.prev/python/sglang). pytest run from a git worktree
    still imports library code from here, so worktrees CANNOT be used to
    baseline library changes -- only test-file changes. Baseline by checking the
    commit out in this tree.

  * 13 failures in test/registered/unit/layers/quantization/ are pre-existing on
    SM120 and identical on upstream main (verified by real checkout, not a
    worktree): mm_fp4 has no 'trtllm' backend on SM120, and the trtllm/cutedsl
    kernels fail to JIT-build. The stack adds 3 passing tests and no failures.
