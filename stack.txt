EVALUATED AND DELIBERATELY NOT INCLUDED
==============================================================================

  PR #39721 / #39722 / #39723 / #39724  @Shunkangz
      [Qwen3.8 CP 1/4 .. 4/4] Collocated prefill context parallelism
      https://github.com/sgl-project/sglang/pull/39724  (4/4 contains 1..3)

      Reviewed 2026-09-16, not merged. Reasons:

      1. Wrong interconnect. These cards have no NVLink (`nvidia-smi nvlink -s`
         reports 'Device does not have or support Nvlink'; topology is NODE, i.e.
         PCIe via host bridges). CP adds per-layer all-gathers of K/V and index-K
         on top of TP traffic. #39722 was benchmarked on 4x B200 over NVLink.

      2. The required config removes most of the serving setup. The hook in
         #39723 refuses to start unless radix cache AND chunked prefill are
         disabled, plus no EP / PP / a2a backend / DP attention / spec decode /
         PD, and it force-disables prefill CUDA graphs. That also makes it
         mutually exclusive with HiCache (#39862 + #39893).

      3. Conflicts with #38209 above. #39721 rewrites
         QSAMetadata.get_prefill_mqa_inputs against the pre-#38209 Python loop.
         One file, two hunks, but it is a semantic conflict: the resolution is to
         keep the fused packer and branch the row-range computation on whether
         query_sequence_ids is set. build_qsa_row_ranges still exists, so it is
         tractable -- it just is not a mechanical merge.

      4. All-or-nothing. _SUPPORTED_MODELS is empty until 4/4 registers
         Qwen4ExpForConditionalGeneration, so 1/4-3/4 alone are dead code.

      Local branches pr39721..pr39724 are kept for reference if long-context
      prefill is revisited.

==============================================================================
CAVEATS
==============================================================================

  * HiCache (--enable-hierarchical-cache) needs BOTH #39862 and #39893. They fix
    different halves of issue #39830 (PLE slot side state, and QSA indexer state)
    and each was measured with the other applied. Issue #39830 is still open
    upstream; neither PR is merged. Two residuals of the same defect class were
    found in audit and are fixed locally by qsa_hicache_residual_fixes (30-31):
    an unreadable storage page killing a daemon IO thread (the author's own
    open question in the #39830 thread), and the retraction backup dropping
    QSA compressed-K rows. Nothing here has been run end-to-end on this
    host with HiCache on -- the 0/15 -> 15/15 numbers are the #39893 author's, on
    1x B200, and CPU tests only cover 30-31 locally. Validate on this box before
    trusting it in production.
    https://github.com/sgl-project/sglang/issues/39830

  * #39862 needed a follow-up fix (038667befd). Upstream unit tests build
    MambaPoolHost with __new__ and never run __init__, so the attributes #39862
    adds there were missing and every reader raised AttributeError. It broke two
    tests that pass on upstream main; the second only appeared once the
    2026-09-17 upstream merge brought in the NPU mamba test (#32500). Empty
    class-level defaults restore the intended no-op path.

  * #39893 needed a test-isolation fix (01eba4bf8d). Its new test file calls
    reset_context() in teardown -- the documented idiom -- which drops the
    context that test_qsa_indexer.py published at module import. pytest imports
    all selected modules before running any test, so running the qsa directory in
    one process failed 4 indexer tests with "config namespace 'exec' not
    published". CI runs per-file and never saw it. The indexer test now
    republishes per test.

  * sglang is installed EDITABLE against this checkout
    (/root/sglang/sglang.prev/python/sglang). pytest run from a git worktree
    still imports library code from here, so worktrees CANNOT be used to
    baseline library changes -- only test-file changes. Baseline by checking the
    commit out in this tree.

  * Run test files PER FILE, the way CI does. A single pytest process over a
    directory lets one file's published/reset context change another's result,
    in both directions.

  * Known-failing, not caused by this stack:
      - 13 in test/registered/unit/layers/quantization/ -- pre-existing on SM120,
        identical on upstream main (verified by real checkout). mm_fp4 has no
        'trtllm' backend on SM120; trtllm/cutedsl kernels fail to JIT-build.
      - test_qsa_strided_zero_fill.py OOMs when a server is holding the GPUs;
        it wants 2 GiB free. Environmental.
